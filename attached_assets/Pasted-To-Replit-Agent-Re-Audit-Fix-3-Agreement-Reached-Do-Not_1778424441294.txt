  Re: Audit Fix #3 — Agreement Reached, Do Not Build Yet

  I agree with your final presence-mode correction.

  Final decision:

  1. sharingMode = presence should NOT keep native background GPS running by itself.

  Presence should mean:
  the app knows the user is alive and reachable,
  but it is not silently collecting precise GPS in normal calm time.

  That matches StillHere’s promise:
  “safety without surveillance.”

  2. Presence mode may allow native GPS only when there is an active safety purpose:

  Allowed active purposes:

  liveShare
  safeWalk
  driveSafety
  safetyTimer
  incident
  activeShift

  Outside those purposes:

  nativeTrackingAllowed = false
  heartbeatAllowed = true

  3. Preserve the existing concern override.

  If the user enters concern state, missed checkin, SOS, or another real safety incident, the server may still allow coordinates to
  watchers.

  Do not remove that feature.

  4. Add the one-shot location mitigation.

  When policy flips from:

  nativeTrackingAllowed=false

  to:

  nativeTrackingAllowed=true

  because a real safety purpose begins, the client should immediately call Geolocation.getCurrentPosition() once, then start
  BackgroundGeolocation.

  Reason:
  This protects privacy during normal time, but still helps watchers get a location quickly when something is actually wrong.

  5. Accept the temporary “Locating…” state.

  If presence users have no recent GPS because we were respecting privacy, watchers may briefly see “Locating…” at the start of a
  concern.

  That is acceptable.

  Privacy promise is more important than silently collecting location all day.

  6. Keep server redaction behavior unchanged.

  Presence mode should still return lat/lng=null to watchers during normal time.

  Concern override should still work during real safety events.

  7. Final agreed policy matrix:

  nativeTrackingAllowed = true only if:

  user is authenticated
  sharingMode is not paused
  locationMode is not off
  and one of the approved active purposes exists

  OR

  locationMode is both and sharingMode allows location

  OR

  locationMode is on_shift_only and an active shift exists

  For presence specifically:

  presence does not allow ongoing GPS by itself
  presence allows heartbeat
  presence allows GPS only during active safety purpose

  8. Keep the 5 minute / 3 failed poll grace rule.

  9. Strip lat/lng/acc from heartbeat server-side whenever nativeTrackingAllowed=false.

  10. Use the central server-side tracking policy helper as the source of truth.

  Do not build yet until the founder gives final authorization.

  Once authorized, build this exactly and report back with changed files, policy cases tested, and verification logs.
