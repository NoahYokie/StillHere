Task — Build Family Mode Foundation for StillHere

Goal:
Create a new feature called **Family**.

Family Mode lets trusted family members monitor each other’s safety on the map, receive safety updates, and coordinate during emergencies.

Important:
This is NOT parental control.
Do NOT build app usage tracking, app blocking, phone spying, screenshots, browser history, or device surveillance.

StillHere Family is about:

* live safety status
* check-ins
* SOS
* arrivals
* journeys
* location sharing with consent
* emergency coordination

Keep StillHere original colors and design style.

---

Add a new side menu item:

Label:
Family

Icon:
Use a family/users/heart style icon.

Place it near:
Messages / Guardians / Safety Circle

Route:
`/family`

---

# 2. Family data model

Create basic Family Group support.

A family should have:

* id
* name
* adminUserId
* createdAt
* updatedAt

Family members should have:

* id
* familyId
* userId
* role: `admin | adult | teen | child`
* status: `active | invited | paused | removed`
* sharingMode: `precise | area | presence | paused`
* parentalConsentRequired: boolean
* parentalConsentGranted: boolean
* invitedBy
* createdAt
* updatedAt

Important:
One family has one admin initially.
Admin can invite, remove, pause, and manage under-16 members.

---

# 3. Under-16 rule

If member age is below 16:

* require parental/admin permission
* show clear label:
  `Parental permission required`

Do not allow full monitoring until permission is granted.

If age is unknown:

* treat as adult by default
* do not block
* but allow admin to mark someone as under 16 manually

Do not collect more personal data than needed.

# 5. Admin controls

Admin can:

* create family
* invite member by phone number
* remove member
* pause member access
* change member role
* approve under-16 member
* view family safety overview

Non-admin members can:

* view family members who share with them
* manage their own sharing mode
* leave family

---

# 6. Privacy controls

Every user must keep control over what they share.

Each member should be able to choose:

* Precise location
* Area only
* Presence only
* Paused

Use existing privacy mode logic if already built.

Important:
Family admin should NOT automatically override adult privacy settings.

For under-16 accounts:
admin/parent can manage sharing settings after consent is granted.

# 12. Backend APIs

* GET `/api/family`
* POST `/api/family`
* POST `/api/family/invite`

Permissions:

* members can update their own sharing mode
* adults control their own sharing
* under-16 requires admin consent
