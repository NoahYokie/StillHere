Task — Fix Family Invite Delivery (SMS + Awareness)

Goal:
Make Family invites real and usable.

Right now invites are stored in the database but not delivered to the user. We need to send an SMS so the invited person knows they’ve been added.

---

# 1. Send SMS on invite (CRITICAL)

When POST `/api/family/invite` is called:

After creating the invite row, send an SMS using existing Twilio setup.

SMS content should be:

"[Inviter Name] added you to their StillHere Family for safety.
Join here: https://stillhere.health
You'll be able to share safety updates and stay connected."

Keep it:

* calm
* non-invasive
* not alarming

---

# 2. Prevent duplicate SMS spam

If the same phone number is invited multiple times within a short period:

* Do NOT send another SMS
* Use a 5–10 minute dedupe window

Return:
{ deduped: true }

---

# 3. Handle existing users vs new users

If phone number already belongs to an existing StillHere user:

* Still send SMS
* But slightly change message:

"[Inviter Name] added you to their StillHere Family.
Open the app to view and accept."

---

# 4. Add invite status visibility

On Family page:

For invited users:

* Show status:
  Invited

Add small text:
"Waiting for them to join"

---

# 5. Accept invite (basic version)

When a user logs in:

If their phone matches an invite:

* Automatically link them to the family
* Update status:
  active

Do NOT require complex accept flow yet.

---

# 6. Logging

Add structured logs:

[INVITE] SMS sent to +61XXXXXXXX
[INVITE] SMS skipped (deduped)
[INVITE] Linked existing user to family

---

# 7. Do NOT build yet

Do not add:

* push notifications for invites
* email invites
* deep invite management UI
* accept/decline screens

Keep this simple and working first.

---

# 8. Acceptance report

Return:

1. where SMS is triggered in code
2. how dedupe works
3. SMS message content used
4. how existing users are handled
5. how new users are handled
6. how auto-link on login works
7. confirmation it uses existing Twilio config
8. any edge cases

---

Goal:
When I invite someone → they instantly receive a message and know what to do.
