Task 5 — Watcher Trust UX

We are now focusing on transforming system data into clear, human, trust-building communication.

---

# 🎯 OBJECTIVE

Make the Watcher immediately understand:

1. Is the person okay?
2. When were they last active?
3. Is the phone alive?
4. Is GPS working?
5. Should I worry right now?

---

# 🧠 CORE PRINCIPLE

Separate TWO THINGS clearly:

## 1. Connection Status (Heartbeat)

→ Is the phone alive?

## 2. Location Status (GPS)

→ Do we know where they are?

These must NEVER be confused.

---

# 🔧 BUILD REQUIREMENTS

## 1. New Status Model (UI Layer)

Create structured display states:

### 🟢 Active

* "Updated just now"
* "Everything looks normal"

---

### 🟡 Quiet

* "No updates in the last X minutes"
* "Last seen near [location]"

---

### 🔴 Concern

* "We haven’t heard from [Name] for X minutes"
* "Trying to reach them now"

---

## 2. Add CONNECTION vs LOCATION distinction

Examples:

### Case A — Good connection + GPS

"Live location updating"

### Case B — Connection alive, GPS missing

"Phone is online, waiting for location"

### Case C — No heartbeat

"Phone unreachable — last seen X minutes ago"

---

## 3. "Last Seen" Intelligence

Display:

* "Last seen 2 minutes ago near Bondi Beach"
* NOT just timestamp

Must combine:

* last heartbeat
* last location snapshot

---

## 4. Recovery Feedback (VERY IMPORTANT)

When user returns from Quiet → Active:

Show:

* "Back online just now"

This creates:

* relief moment
* emotional trust

---

## 5. Map Integration

Each person marker must show:

* status color (green / yellow / red)
* short readable label:

  * "Active"
  * "Quiet"
  * "Concern"

Optional tooltip / tap:

* full explanation text

---

## 6. Stale Location Indicator

If location > 5 min old:

* show:
  "Location may be outdated"

* DO NOT present it as live

---

## 7. Tone Requirements

Language must be:

* calm
* human
* reassuring
* NOT technical

❌ "Heartbeat timeout"
❌ "State: quiet"

✅ "No updates in the last 6 minutes"
✅ "Phone is still on, waiting for location"

---

# 📦 OUTPUT REQUIRED

Report back with:

1. All UI states implemented
2. Example screenshots or descriptions of each state
3. Where status appears (map, list, profile, etc.)
4. Confirmation that connection vs location are clearly separated

---

# ⚠️ DO NOT TOUCH

* heartbeat logic
* safety state engine logic
* location-service

This is UI + interpretation layer ONLY.

---

* state changes (quiet → active)

---

Build it like you are designing for:
