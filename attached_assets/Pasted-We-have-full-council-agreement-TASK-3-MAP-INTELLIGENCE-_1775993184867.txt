# 🔧 TASK 3 — MAP INTELLIGENCE SYSTEM (AUTO-ZOOM + CAMERA LOGIC)

## 🎯 OBJECTIVE

Fix map zoom behavior to be intelligent, safety-aware, and user-friendly.

The map must:

* never zoom out too far unnecessarily
* focus on the most important person/event
* behave predictably

---

# 🧠 CORE RULE — ADAPTIVE CAMERA

Camera behavior must be driven by:

1. safety state
2. activity (movement)
3. user interaction

---

# 1. PRIMARY FOCUS SYSTEM

Determine a single “focus target”:

Priority order:

1. user in `"concern"`
2. user with active safety event (SOS, Safe Walk, Safety Timer)
3. selected user (if UI selection exists)
4. moving users (speed threshold)
5. fallback: current user / self

If multiple candidates:
→ choose most recently updated / triggered

---

# 2. CAMERA MODES

## A. Single focus target

* center on target
* zoom to neighborhood/street level

## B. Multiple nearby users

* use `fitBounds()` with padding
* enforce minimum zoom level

## C. Users far apart

* allow fitBounds
* BUT:

  * apply zoom cap (no extreme zoom-out)
  * allow tap to focus one user

---

# 3. ZOOM LIMITS

Add a minimum zoom level:

* never zoom out beyond city/neighborhood level

Prevent:

* state-level or country-level zoom

---

# 4. FILTER BAD DATA

Exclude users from camera calculation if:

* location older than **180 seconds**
* accuracy > **500 meters**

They can still render on map, but NOT influence zoom.

---

# 5. VELOCITY-AWARE ZOOM

Adjust zoom based on movement:

* driving → zoom out slightly (look ahead)
* walking → medium zoom
* stationary → tighter zoom

---

# 6. LOCATING GUARD

If:

```id="m1"
isLocating === true
```

Then:

* DO NOT move camera yet

Wait until first valid GPS fix.

---

# 7. MANUAL OVERRIDE

Detect user interaction:

* pan
* zoom

When detected:

* disable auto camera

Show:

* “Re-center” button

When button tapped:

* restore auto behavior

---

# 8. SAFETY OVERRIDE

If any user is:

* `"concern"`
* OR has active safety event

Then:
→ camera MUST prioritize them
→ ignore full group view

---

# ⚠️ DO NOT CHANGE

* marker rendering logic
* location-service
* heartbeat system
* safety state engine

This is camera behavior only.

---

After completion, report:

4. How stale/low-accuracy users are filtered
5. How manual override is detected
6. Any edge cases or conflicts found
