  One required adjustment:

  Do not make processor cleanup cron-only.

  Use this sequence:

  1. Read processor IDs into memory.
  2. Insert processor_cleanup_queue row with all needed steps.
     If queue insert fails, abort deletion and return 500.
  3. Attempt processor cleanup inline with short timeouts:
     - Stripe subscription cancel
     - Stripe customer delete
     - RevenueCat delete
     - outbound_send_log purge
  4. For each successful inline step, mark/remove that step from the queue.
  5. For each failed or timed-out step, keep it in steps_remaining for cron retry.
  6. Revoke all sessions.
  7. Delete Postgres user and cascade app data.
  8. Clear current session cookie.
  9. Return 200 with processorWarnings if any processor step is still pending.

  Reason:
  Account deletion should not be blocked by Stripe/RevenueCat, but billing cancellation should be attempted immediately so a user
  is not charged while waiting for cron.

  If implementing inline cleanup with safe timeouts is too complex for Batch 2, explain why and propose the safest minimal
  alternative.

  Other requirements:

  Stripe:
  - stripe.subscriptions.cancel if subscription exists and is active.
  - stripe.customers.del after subscription cancel or if no subscription.
  - resource_missing counts as success.

  RevenueCat:
